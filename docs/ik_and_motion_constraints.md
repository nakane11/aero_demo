# IK・事後検証・軌道計画の制約一覧

握手姿勢を求める二段階の IK (干渉回避付きバッチ IK → 押し込み区間 + 後処理 IK)、
その間に挟む干渉の事後検証、接近軌道の計画、押し込み後の横並び移動で、それぞれ何を制約・コストに
入れているかをまとめる。値はすべて 2026-10-15 時点のコードの既定値 (5 節の人の手首は 2026-10-22)。定数名は `solve_palm_ik.py` (`spik`)、
`plan_handshake_motion.py` (`phm`)、`side_by_side_transition.py` (`sbs`)
のもの。各段階で考慮する干渉・台車の可動域を図で見るには
[handshake_pipeline_stages.md](handshake_pipeline_stages.md)。

全体の流れ:

```
人物ごと (solve_palm_ik.main / run_camera_pipeline_test.HandshakePlanner.plan)
  └ 台車 x の窓ごと (±0.15 m → ±0.3 m → 無制限, solve_person_ik_side_by_side)
      ├ 第1段: 干渉回避付きバッチ IK (向き 3 × 初期値 512 を 1 バッチ、目標は hover)
      └ 候補選択 (pick_verified_candidate): コスト昇順に
          ├ hover の事後検証 (自己干渉の貫通 + 人体から 5 cm、差し出した手まわりだけ 2 cm)
          ├ 第2段: 押し込み区間 (solve_press_in): 曲線上 8 点の IK、最後の点が後処理 IK (掌 + 視線)
          └ 押し込み区間の事後検証 (自己干渉 + 手まわり以外の人体から 5 cm)
軌道計画 (plan_person_motion)
  └ 接近開始位置の候補ごと
      ├ lead-in の検証
      └ 線形補間 → jaxls 最適化 の順に作って全 waypoint を検証
押し込み後の横並び移動 (sbs.plan_transition)
  ├ 移動先: 台車も動かすバッチ IK (手を下ろした位置 3 つを 1 バッチ)
  └ 経路: 押し込み姿勢から waypoint ごとに IK を解き進めて検証
実機 (--auto-execute)
  ├ hover 到達後、押し込みの最終補正 (refine_post_process、同じ曲線を解き直す)
  └ 押し込みの 4 秒後に横並び移動
```

## 0. 共通の前提

### 干渉回避の考え方 (要約)

| 項目 | 値 | どこで使うか |
|---|---|---|
| 人体から離す距離 (最適化) | **6 cm** (`spik.DEFAULT_COLLISION_MARGIN` = `phm.DEFAULT_COLLISION_ACTIVATION_DISTANCE`) | hover の IK のペナルティの効き始め、軌道最適化の効き始め |
| 人体から離す距離 (検証) | **5 cm** (`spik.DEFAULT_HOVER_HUMAN_CLEARANCE`、`phm.DEFAULT_HUMAN_CLEARANCE`、`sbs.TRANSITION_HUMAN_CLEARANCE`、`spik.PRESS_IN_HUMAN_CLEARANCE`) | hover 姿勢の事後検証、接近軌道 (lead-in・全 waypoint)、押し込み区間 (手まわり以外)、横並び移動の事後検証 |
| 差し出された手まわりから離す距離 | **2 cm** (`spik.OFFERED_HAND_CLEARANCE`) | hover の事後検証と接近軌道。押し込み区間では見ない、横並び移動では 5 cm (ロボットの肘から先だけ除外) |
| 自己干渉の許容貫通 | **0 mm** (`DEFAULT_COLLISION_VERIFY_TOLERANCE` = `phm.DEFAULT_MOTION_COLLISION_VERIFY_TOLERANCE`) | IK・軌道の事後検証 |
| ロボットの形状 | 指なしモデル + 手の箱 2 個 (下の「干渉ジオメトリ」) | IK・軌道最適化・自己干渉の事後検証 |
| 人体との距離を測るモデル | 指ありモデル (`--collision-verify-model mixed`) | IK・軌道の事後検証 |

**差し出された手まわり** = 差し出した側の掌・指 5 本・同じ側の前腕 (肘–手首) の 7 本
(`offered_hand_obstacle_indices`)。hover は人の掌から約 2 cm しか離れない
(hover = 掌 + 法線 × 0.02 − 指先方向 × 0.15、1 節) ので、この 7 本だけは全身と同じ距離を取れない。

人体との判定は貫通ではなく「その距離だけ離れているか」だけで行い、貫通の判定は自己干渉の組だけで
行う (`self_collision_pairs`)。人体の円柱は腕・胴体とつながっているので、どこかで貫通して
いれば必ずいずれかの円柱がロボットのリンクの表面を横切り、そこで表面サンプルからの距離が
ほぼ 0 以下 (符号付きなので内部なら負) になり、基準距離未満として捕まるため。

各段階の基準 (差し出された手まわり以外は全身):

| 段階 | 全身 | 手まわり |
|---|---|---|
| hover の IK (ペナルティ) | 6 cm | 2 cm (前腕を細らせて 2 cm 相当、掌・指はペナルティに入れない) |
| hover の事後検証 | 5 cm | 2 cm |
| 押し込み区間 (途中の 7 点 + 最終の 1 点) | 5 cm | 見ない (掌に触れる) |
| 接近軌道・lead-in | 5 cm | 2 cm |
| 横並び移動 | 5 cm | 5 cm (ただしロボットの肘から先 × 人の差し出した手・前腕は見ない) |

### 関節可動域 (全段階共通)

`main` 起動時に `robot` の関節自体を書き換えるので、以降のすべての IK・
軌道計画に効く。

| 関節 | 制限 | 理由 |
|---|---|---|
| `{r,l}_elbow_joint` | 下限を -120° に (`ELBOW_MIN_ANGLE_DEG`) | 曲げきると前腕と上腕が平行に近い不自然な姿勢になる |
| `ankle_joint` | 上限 90° → 63° (低くなる側を全域の 30% 削る, `LEG_LOW_SIDE_MARGIN_RATIO`、`--leg-low-margin`) | 腰が低いと実機の押し込みで指令に追従できない。10/19 の実機で hover から沈みすぎ (ankle/knee 73/-76°) と指摘があり 10% → 30% (5.5 節) |
| `knee_joint` | 下限 -90° → -63° (同上, `restrict_leg_range`) | 同上 (曲げすぎない) |
| `waist_p_joint` | 上限 34.95° (URDF) → 32.5° (`WAIST_P_MAX_ANGLE_DEG`, `restrict_waist_range`) | 実機は負荷なしでも 32.96° で止まる (ハード上限) |
| `neck_p_joint` | 上限 55° (URDF) → 44.5° (`NECK_P_MAX_ANGLE_DEG`, `restrict_neck_range`) | 実機は 45.44° で止まる |
| `neck_r_joint` | 視線 IK では動かさず 0° に固定 (`NECK_ROLL_FIXED_ANGLE`, `gaze_link_list`) | 実機の首のピッチ・ロールは左右 2 本のアクチュエータの差動で、ロールを付けると片側のストロークが端に当たりピッチ・ロールとも指令に届かない。実機の `/joint_states` の neck_r は符号が逆なので 0 以外では TF もずれる |
| `{r,l}_hand_y_joint` | 0 に固定 (`lock_fixed_joints`) | 実機にモータが無い。動かすと左手の向きが 180° 前後ずれる |

第1段のバッチ IK だけは、この上からさらに各関節の上下を全域幅の 5% ずつ (2026-10-20 に 10% から変更)
狭める (`restrict_joint_range_margin`, `DEFAULT_COLLISION_IK_JOINT_LIMIT_MARGIN_RATIO`)。
バッチ IK の呼び出し前後だけ適用して戻すので、後処理 IK・軌道計画は本来の
(上表適用後の) 可動域で解く。

### IK の手先

`{r,l}arm_end_coords` を `{r,l}_eef_grasp_link` から局所 +X (手首 → 指先) に
4 cm ずらす (`shift_grasp_point`, `GRASP_POINT_OFFSET_X`、`lock_fixed_joints`
から呼ぶ)。人の掌に当たる位置が手首寄りだったため。バッチ IK・軌道計画は
`move_target` の親リンクからの相対位置を読むので、IK・干渉回避・押し込みの
すべてに効く。実機 TF の `r_eef_grasp_link` (差し出し手の判定の基準) は
ずらしていない。

### 動かす関節

- IK・軌道計画とも `{arm}arm_whole_body` (脚のリフター機構 + 片腕) を動かす。
  使わない方の腕は肘を伸ばして下ろした姿勢で固定 (`seed_arm_pose`)。
- 台車 (x, y, yaw) を動かすのは、第1段のバッチ IK・軌道計画・横並び移動の移動先のバッチ IK。
  押し込み区間は各点で台車を hover の位置から指先方向へ平行移動 (向きは変えない) させてから
  腕の IK を解く (台車自体は IK の変数にしない)。
- 首を解くのは押し込み区間の最後の点 (後処理 IK) と最終補正 (と 5 節の横並び移動) だけ。
  `robot.head` の 3 関節のうち首ロールを除いたヨー・ピッチの 2 関節で解き、ロールは 0° に
  固定する (`gaze_link_list`)。押し込み区間の途中の点の首は最終姿勢の角度に揃える。

### 干渉ジオメトリ

| 対象 | 形状 |
|---|---|
| ロボット (IK・軌道最適化・自己干渉の判定) | 指なしモデル (`Aero(use_hand=False)`) の各リンクを box/cylinder/sphere のプリミティブで近似したもの (`apply_collision_model`)。指なしの URDF は左手の `l_hand_y_joint` の取り付け位置だけが指ありの URDF と 4 cm 違うため、`lock_fixed_joints` の中で指ありの値に合わせる (`align_hand_mount_with_hand_model`)。台車は元 URDF の box (`wheel_base_link`) に加え、前方の高い部分を干渉専用のリンク `wheel_base_front_link` の box として足す (`aero_demo.collision_model.EXTRA_COLLISION_BOXES`)。手は下の「手の箱」に置き換える |
| ロボット (人体との距離の判定) | 指ありモデル (`load_aero(use_hand=True)` に `apply_collision_model`)。IK を解く指なしのロボットの関節角・台車位置を写して測る (`VerificationPairs.sync_from`) |
| 人体 | 骨格から作る 26 本の `Cylinder` (`human_body_obstacles`)。詳細は下 |

**手の箱** (`apply_hand_box`、`hand_box_primitives`): 指ありモデル (既定の指の角度) の手と
指の干渉形状の頂点を、手のリンク (`{arm}_hand_link`) の座標系で包んだ箱 2 個。

| 箱 | 大きさ (幅 × 厚み × 長さ) | 置き方 |
|---|---|---|
| 掌 + 4 本の指 (人差し指〜小指、指の付け根の土台を含む) | 8.3 × 6.6 × 18.5 cm | `{arm}_hand_link` 自身の形状 (`collision_mesh` と `collision_primitive`) を置き換える |
| 親指 | 8.7 × 3.9 × 8.7 cm | `{arm}_hand_link` に固定した干渉専用のリンク `{arm}_thumb_box_link` (`HAND_THUMB_BOX_LINK`) |

- 手首側 (+z) は元の手の形状の端で切り詰める (手首のリンクと常に重なるのを避ける)。
- 親指を分けるのは、横に約 5 cm 張り出しているため。1 つにまとめると指先まで幅 13 cm の
  箱になる (以前の 13 × 7 × 20 cm の箱)。4 本の指も別の箱 (厚み 3.8 cm) にした 3 個と
  比べても、合成人物 26 人の IK・軌道の成功数は変わらなかった。
- 指ありモデルをそのまま使わないのは、干渉形状を持つリンクが 35 → 85 本、自己干渉の組が 472 →
  3093 組、人体との組が 2210 → 5303 組に増え、軌道最適化 1 回が延びるため (2026-10-01 の計測で
  片腕約 1.3 → 4.8 秒)。
- 指の曲げ伸ばし (実機で握るとき) はどのモデルにも反映されない。

人体の 26 本の内訳:

- 骨 14 本 (`HUMAN_COLLISION_SEGMENTS`、胴体 3 本を含む)。半径は頭–首 0.10、首–肩 0.09、
  上腕 0.06、前腕 0.04、大腿 0.09、下腿 0.06 m。頭の端点 `HeadCenter` は両耳の
  中点 (耳が欠けたら Nose。Nose は顔の表面にあり、合成データでも首–頭の軸から
  6 cm 前にある)。
- 胴体 3 本 (左右の肩–腰、腰–腰) の半径だけは、実測の肩幅・腰幅 × 0.5 ×
  0.55 + 衣服のマージンを 0.08〜0.20 m にクリップした値 (`_torso_segment_radius`)。
  マージンは合成データ 0.03 m (`TORSO_RADIUS_MARGIN`)、実カメラ 0 m
  (`SURFACE_TORSO_RADIUS_MARGIN`)。左右の柱の軸は肩・腰の関節そのもの。
- 実カメラの骨格は関節が体の表面 (深度の点) にあるので、干渉判定に使う骨格だけ
  カメラから離れる水平方向へずらす (`shift_torso_joints_from_surface`、
  `--torso-surface-offset`。実機ノードは既定 0.07、`solve_palm_ik.py`・
  `plan_handshake_motion.py` は既定 0 なので実データを解くときは指定する)。ずらす量は
  首・肩・腰 7 cm、Nose 8 cm、耳 5 cm、肘 4 cm、手首 3 cm、膝・足首 5 cm
  (`LIMB_SURFACE_OFFSETS`)。ずらした骨格には目印の点 `SurfaceShifted` が入り、胴体の
  マージンの切り替えに使う。立ち位置・向きの計算は元の骨格を使う。合成データ (SMPL) は
  関節が体内にあるので使わない。
- 左右の手それぞれに、掌 1 本 (半径 0.05 m・厚み 0.02 m) と指 5 本 (半径 0.008 m)。
- 検出できなかった関節は、親関節があれば鉛直下向きに伸ばした位置で補う
  (`_fill_missing_joints_straight_down`)。前腕の手首端は掌の円柱の表面まで延長する。
- 親も無い部位は 100 m 先のダミーで埋める (JIT の再コンパイルを避けるため、
  本数は常に 26 本)。

### 干渉の組み合わせ (ペア)

| 用途 | ペア |
|---|---|
| 第1段バッチ IK の最適化 | `scripts/collision_pairs.json` の 8 組 (台車・胴体・肩・上腕 × 人の脛・体幹、下の「最適化で使う干渉ペアの選び方」) と、ロボットの手・親指の箱・手首 (`hand_yaw_link`)・前腕 (`OFFERED_HAND_PENALTY_LINKS`) × 差し出された前腕 1 本の 4 組 (前腕の円柱は半径・長さを (6 cm − 2 cm) 細らせ、2 cm で効くようにする。掌・指は組に入れず、hover の事後検証で 2 cm を見る)。自己干渉の組は無い。**JSON が無いと干渉回避と事後検証の両方を無効にして解く** (0 組の JSON なら干渉回避だけを無効にし、事後検証は行う) |
| 自己干渉の事後検証 (IK・軌道共通) | 指なし + 手の箱の全リンク同士 (35 本、472 組) から `self_collision_ignored` の組を除いたもの。除くのは、干渉ジオメトリを持つリンクだけでたどった関節のつながりが 3 段以内の組、既定の姿勢で既に貫通している組、`SELF_COLLISION_IGNORE_PAIRS` (前腕 × 指ありモデルの親指の付け根。手首の角度によって近似形状が 1 mm 未満で触れるだけで、実機では当たらない) |
| 人体との距離の事後検証 (IK・軌道共通) | 指ありモデルの全リンク × 人体 26 本 (2210 組、`VerificationPairs.clearance_pairs`) |
| 軌道最適化 (jaxls) | 指なし + 手の箱の全リンク (`collision_link_list_for_arm`) × 人体 26 本、および自己干渉 (リスト上で隣り合わない全組。`collision_pairs.json` は使わない)。人体のうち差し出された手まわりは、掌・指を遠くのダミーに置き換え、前腕は効き始めで 2 cm になるよう細らせる (`human_body_cylinder_obstacles(hand=)`) |

`--collision-verify-model` (`solve_palm_ik.py`・`plan_handshake_motion.py`・実機ノード共通) で
事後検証のモデルを選べる: `mixed` (既定、上表)、`nohand` (人体との距離も手の箱で測る)、
`hand` (自己干渉も人体との距離も指ありモデル)。比較は 7 節。

### 最適化で使う干渉ペアの選び方 (2026-09-30)

`tools/build_collision_pairs.py` は、干渉回避なしで解いた解を事後検証と同じ組・同じ判定
(`build_collision_verification_pairs` の組を `collision_pair_distances` で測る。自己干渉は
`self_collision_depth` の貫通の深さ) で調べ、1 mm より深く貫通していた人数の多い順に並べ、
上位を採る。ランキング用のデータは seed 10 の 2000 人 (IK 対象 259 人)。
(このときの事後検証は指なし・人体とも貫通で判定していた。)

上位 8 組 (干渉した人数):

| 順位 | 組 | 人数 |
|---|---|---|
| 1 | `wheel_base_link` × `RKnee-RAnkle` | 100 |
| 2 | `body_link` × `RShoulder-RHip` | 99 |
| 3 | `wheel_base_link` × `LKnee-LAnkle` | 97 |
| 4 | `body_link` × `LShoulder-LHip` | 96 |
| 5 | `l_upperarm_link` × `RShoulder-RHip` | 70 |
| 6 | `r_upperarm_link` × `LShoulder-LHip` | 63 |
| 7 | `l_shoulder_center` × `RShoulder-RHip` | 63 |
| 8 | `r_shoulder_center` × `LShoulder-LHip` | 60 |

組を増やすと棄却は減るが第1段が重くなり、12 組以上では合計が遅くなる (seed 2 の 131 人で
4/8/12/16 組の後処理まで成功 126/126/126/125 人)。4 組と 8 組は差が小さいため 8 組にした。
初期値の数は 512 と 256 を軌道計画まで含めて比べ、512 (既定のまま) にした。

### 人体の胴体の大きさの検証 (2026-10-02〜03)

`data2/session1.bag` の深度と `data2/skeletons` の骨格で、胴体の円柱と実際の体の表面を比べた
(data2 は現在の `data/real/2026-09-30_session1/`、[`test_data.md`](test_data.md))。

**前後**: 関節が体の表面にあるため、円柱の軸が胸の表面に乗り、見えている体より胴体が
中央値 8.7 cm、首–肩が 5.8 cm 前に出ていた。体幹を 7 cm ずらす (上の
`shift_torso_joints_from_surface`) と胴体 +2.3 cm、首–肩 -0.8 cm になり、data2 の人手
ラベル 90 件で IK 21 → 28 件、軌道計画まで 18 → 20 件に増えた。

**左右**: 体がほぼ正面を向いた 124 フレームで、人の座標系 (肩を結ぶ水平方向) の高さごとに
横幅を測った (人が画像の右端にいて左側は画像外・背景の棚が混ざるので、右側だけで評価)。

| 肩からの高さ | 腕を体側に下ろしている | 腕を体から離している |
|---|---|---|
| 0 cm (肩) | +5.9 cm | +4.3 cm |
| -10 cm | +4.1 cm | +3.6 cm |
| -20 cm (胸) | +0.9 cm | +7.9 cm |
| -30 cm | -1.3 cm | +5.4 cm |

(値は円柱の外側の面の、実測の体 (腕を含む) からの張り出しの中央値。) 軸が肩の関節にある
ので円柱は肩の関節から半径 (約 0.11 m) 外まで広がり、実際の体は腕込みでも 6〜8 cm 外まで
しかない。腕を下ろしていれば胸より下は腕が張り出しを埋める。

肩側の端点を肩線に沿って内側へ寄せる案は、寄せた柱を第1段バッチ IK の干渉コストにも使うと
収束が減って IK 成功が減り (合成 42 人で 35/37/34 → 33/34/31)、コストだけ太い柱のまま
事後検証・軌道計画だけ寄せても効果は +1〜2 件程度で、肩の横の実際の体からの余裕も約 8 cm に
縮むため、**採用しなかった**。

成功数を比べるときは、人物ごとにバッチ IK の乱数シードを決め直していること
(`solve_palm_ik.py` の人物ループ冒頭、`zlib.crc32` でファイル名から) が前提。
以前は main の冒頭で 1 回決めるだけだったので、ある人の x の窓の解き直し回数が変わると
以降の全員の初期値がずれ、関係ない人の成否まで変わっていた。

### 頭・腕・脚のずらしと胴体のマージン (2026-10-14)

10/13 実機の試行 22 の bag (ARMED 直前の深度 6 枚) で、深度の「測った面の手前は空いている」
という観測に対し、干渉の円柱がどれだけ入り込んでいるか (p90) を測った。

| 部位 | 変更前 | 変更後 |
|---|---|---|
| 頭 正面 | 7.0 cm | 3.1 cm |
| 胴体 正面 (右/左) | 5.9 / 4.6 cm | 3.5 / 2.1 cm |
| 胴体 横 (右/左、p98) | 10.8 / 8.9 cm | 8.4 / 6.7 cm |
| 下腿 正面 | 3.7〜4.8 cm | 1.6〜1.7 cm |

- 変更は、頭の端点を両耳の中点にしたこと、実カメラの骨格で頭・腕・脚の関節もずらす
  ようにしたこと (`LIMB_SURFACE_OFFSETS`)、実カメラだけ胴体の衣服マージンを 0 にしたこと。
  実カメラの耳も表面の点で、両耳の中点は鼻先の 3.5 cm 奥にしかなかったので耳もずらす。
- 衣服マージンを合成データでも 0 にすると、合成 400 人 (seed 0〜7、IK 対象 48 人) の軌道
  計画まで が 39 → 36 に減った (胴体が細くなって IK の終点が胴体に寄り、接近経路が 5 cm を
  割る)。そのため合成データは 0.03 m のまま。頭の端点の変更は合成でも成功数が変わらない。

## 1. 第1段: 干渉回避付きバッチ IK

`solve_person_ik` → `robot.batch_inverse_kinematics(backend='jax', use_base='planar')`

### 目標

- 位置: **hover 目標** (`palm_target_position` = `press_in_target_position(u=0)`)。
  押し込みの最終目標 (掌 − 法線 × 0.01 m、`POST_PROCESS_TARGET_HOVER_OFFSET`) を、
  掌の法線方向に **0.04 m** 浮かせ (`PRESS_IN_LIFT`)、ロボットの指先 (手先の +Z を掌面へ
  射影した向き、`press_in_slide_direction`) と逆向きに **0.15 m** ずらした位置
  (`PRESS_IN_SLIDE`)。すなわち 掌 + 法線 × 0.03 m − 指先方向 × 0.15 m で、人の掌から約 3 cm
  しか離れない (10/19 までは浮かせ 0.03 m・約 2 cm。実機の試行2で、検出し直した掌が計画から
  3 cm 下・向き 20° ずれ、余裕 2 cm では押し出しの始点が掌の面の反対側 (甲側) にあった。合成 400 人
  で押し込み経路が面の反対側を通る人が 13/54 → 0/53、後処理まで成功 54 → 53。5 cm なら面からの
  最小距離が 0.4 → 3.9 mm)。目標はロボットの手の内部の点なので、表面どうしの距離はこれより 2〜3 cm 短い。
  手先の向きは最終目標と同じ。押し込みはここから指先を押し出しながら詰める (3 節)。
  `--press-in-lift`・`--press-in-slide` で変えられる。
- 姿勢: ロボットの手先 (`{arm}arm_end_coords`) の +X を人の指方向に、
  +Y を掌の法線の逆向きにそろえた姿勢を、+Y 軸まわりに 3 通り回したもの
  (親指側 ±90° / 0° / 小指側 ∓90°, `turn_candidates_deg`)。左腕は
  `_correct_grasp_frame` で補正する。
- 位置・姿勢ともに 6 自由度すべてを拘束する (`position_mask=True, rotation_mask=True`)。

### 台車の可動域 (`base_limits`)

人物は常に Aero の前方 3.0 m (`HUMAN_FRONT_DISTANCE`) に平行移動してから
解くので、以下はその座標系での値。

| 軸 | 既定範囲 | 人物ごとの絞り込み |
|---|---|---|
| x | 0〜6 m | 人の立ち位置 x ± 0.15 m → ± 0.3 m → 無制限 の順に試す (`DEFAULT_BASE_X_STANDING_MARGINS`)。人と横並びにするため (2 節「最終の台車位置」) |
| y | -3〜3 m | 差し出している手の側 (人の中心から見て) だけに絞る (`restrict_base_y_range_to_hand_side`)。空になるなら絞らない |
| yaw | ±90° | 人の正面方向 ± 30° に**置き換える** (`restrict_base_yaw_range_to_human_facing`) |

### コスト (ソフト制約)

| 項 | 重み | マージン (効き始める距離) |
|---|---|---|
| 目標位置・姿勢の誤差 | skrobot の既定 | — |
| ロボット×人体の干渉 (0 節の 8 + 4 組) | 10.0 (`DEFAULT_COLLISION_WEIGHT`) | **0.06 m** (`DEFAULT_COLLISION_MARGIN`) |
| 自己干渉 | (組が無いので実質なし) | 0.02 m (`DEFAULT_SELF_COLLISION_MARGIN`) |
| 関節可動域・台車可動域 | ハード (範囲内にクリップ) | — |

- ロボット側の形状は各リンクのプリミティブ (箱・円柱・球) そのものと人体の円柱の厳密な
  距離で計算する (`collision_geometry='primitive'`, `DEFAULT_IK_COLLISION_GEOMETRY`)。
- 差し出された前腕の 4 組は、hover の事後検証で棄却される候補を減らすため。
- 干渉はペナルティなので、干渉が解消していなくても収束判定は通る。そのため必ず
  事後検証を挟む。

### 収束判定

- 最大 80 反復 (`DEFAULT_COLLISION_IK_STOP`)。jax の勾配降下法は収束に
  関係なく毎回この回数だけ回すので、実質的なタイムアウトとして働く。
- 位置誤差 0.03 m 以下 かつ 姿勢誤差 8° 以下 (`DEFAULT_COLLISION_IK_THRE`/`_RTHRE`)。
  干渉の残差は見ない。
- 初期値は 1 目標あたり 512 個 (`DEFAULT_ATTEMPTS_PER_POSE`)。0 番は種の姿勢
  (`seed_arm_pose`)、残りは関節・台車の可動域内の一様乱数。
- `return_all_attempts=True` で、向き 3 × 512 = 1536 個すべてを候補として返す。

## 2. 候補選択と事後検証

`pick_verified_candidate`

### 並べ替えのコスト

収束した候補すべてについて、hover 姿勢の関節角から直接次のコストを計算し、**昇順**に並べる。

```
cost = Σ w_j · q_j²                                (関節の曲げ量, 単位 rad)
     + 300 · max(0, 0.853 − hover の腰の高さ [m])    (CROUCH_WEIGHT, 腰の沈み込み。10/19 に 100 から変更: 10cm 超沈む 29→22 人、横並び 100% 57 で同じ、1000 では 19 人だが 56)
     + 1000 · max(0, hover の waist_p [rad])²       (BOW_WEIGHT, 腰の前傾 = お辞儀)
     + 30 · |台車が人の立ち位置から人の正面方向にずれた距離 [m]|
     + 30 · |台車の向きの、人の正面方向からのずれ [rad]|
```

| 曲げ量の対象関節 (`JOINT_BEND_COST_JOINTS`) | 重み |
|---|---|
| `shoulder_p` | 0.3 |
| `shoulder_r` | 1.5 |
| `elbow` | 1.0 |
| `wrist_p` | 1.0 |
| `wrist_r` (橈屈・尺屈) | 3.0 |

- 台車の移動量・首・ヨー軸 (`shoulder_y`/`wrist_y`)・脚は曲げ量に含めない。
- 沈み込みの基準 0.853 m は接近の始点の姿勢 (足首 30°・膝 -30°) の腰の高さ
  (`CROUCH_REFERENCE_WAIST_Z`)。以前は「しゃがんでから掌に近づく」不自然な動きを避けて
  沈み込みの重みを 300 (前傾 200) にしていたが、押し込み・横並びで腰を上げない (下の
  「腰を上げない」) ようにしたので、沈んだ腰を浮かせ直す無駄は無くなった。そこで、腰を前に
  倒すより沈む方を選ぶ向きに寄せて **沈み込み 100・前傾 1000** にした。`--crouch-weight`・
  `--bow-weight`。掃引の結果は「腰を上げない」の節。
- 後ろ 2 項の重みは `--front-offset-weight`/`--facing-yaw-weight` (既定 30)。ずれは**押し込み後**
  (台車が押し出しの水平成分だけ指先方向へ近づいた後) の台車位置で測る。立ち位置・向きは
  実カメラでは体幹をずらす前の骨格 (`placement_joint_positions`) から求める。
- 同じコストのときだけ添字順 (向きの優先順 → 初期値の番号) で並べる。

### 最終の台車位置 (人と横並びにする)

コストが関節の曲げ量だけだと、腕を体の横に下ろしたまま繋げる位置、つまり台車が人の立ち位置より
0.3〜0.9 m 前に出た解が最も安くなる。ロボットは人と同じ向きを向くので、終点で人がロボットの
斜め後ろに来てしまい、螺旋の接近の自転が人に背を向けて終わる原因にもなる。次の 3 つで抑える。

- **x の窓**: 台車の x を人の立ち位置 ±0.15 m に絞って解く
  (`restrict_base_x_range_to_human_standing`)。後処理まで通る解が無ければ ±0.3 m → 無制限と広げて
  解き直す (`solve_person_ik_side_by_side`、`--base-x-standing-margins`、既定 `0.15 0.3 -1`、
  負の値は無制限)。解けた窓は結果 JSON の `base_x_standing_margin`。
- **前後ずれのコスト・向きのコスト**: 上の `cost` の最後の 2 項。窓は world の x で取るので、
  人が斜めを向いている分の前方ずれが窓の中に残る。コストは人の向きに沿って測るので、窓の中で
  横並びに近い候補を優先できる。窓で候補を立ち位置付近に集め、コストでその中から選ぶという
  役割分担で、コストは並べ替えるだけなので前に出た候補しか収束しなかった人には効かない。
- x の窓は、人がほぼ ±x を向いていることを前提にする (y の絞り込みが world の y で左右を
  判定しているのと同じ前提)。
- `base_limits` はバッチ IK に trace 対象の引数として渡る
  ([`jax_compilation_cache.md`](jax_compilation_cache.md) 9 節) ので、窓を広げて解き直しても
  再コンパイルは起きない。

現行コードでの前方ずれ・向きのずれの実測は 5 節末尾の「合成データでの現行の結果」。

### 事後検証の順序

1. 差し出さない腕に関わらない組で、hover 姿勢を検証する:
   - 自己干渉の組の貫通 (`collision_pairs_min_distance`、許容 0 mm)。
   - 人体 (全身) から **5 cm** 以上、差し出された手まわりだけ **2 cm** 以上離れているか
     (`human_obstacle_clearances`・`human_clearance_thresholds`、指ありモデル、
     `--hover-human-clearance`。負の値で無効にすると、代わりに人体との組も貫通で見る)。
   ここで落ちれば押し込み区間を解く前に棄却する。
2. 押し込み区間を解く (第2段、3 節)。解けなくても次へ進む (フォールバック用)。
3. 差し出さない腕の関節角を差し替える (`select_other_arm_posture`): hover と押し込み後のうち
   腰が低い方の姿勢で、`OTHER_ARM_POSTURES_DEG` (肩 p・肘の組、(-14, 0) = 体の横に下ろした
   姿勢、(-20, -30)、(-30, -45)、(-40, -60) [deg]) を曲げの小さい順に試し、手と指先が台車の箱
   から 2 cm (`OTHER_ARM_BASE_CLEARANCE`) 以上離れる最初の姿勢を hover・押し込み区間の両方に使う。
   どの姿勢でも離れなければ候補を棄却する。
4. 差し出さない腕に関わる組で、hover 姿勢を 1 と同じ条件で検証する。
5. 押し込み区間 (途中の 7 点 + 最終の 1 点、差し替えた腕の姿勢・各点の台車位置) を検証する:
   自己干渉の貫通 (差し出さない手の指先と台車の箱の距離も含める)、人体は**差し出された手まわり
   以外**の全身から **5 cm** (`PRESS_IN_HUMAN_CLEARANCE`)。手まわりは掌に触れる姿勢なので見ない。
   通らなければ後処理判定の失敗扱い。

距離の測り方:

- 自己干渉: 一方のリンクの表面サンプル (約 1 cm 間隔) がもう一方の凸形状に入り込んだ深さを
  両方向で求め、大きい方を採る (`self_collision_depth`)。貫通していなければ頂点同士の最短距離。
- 人体との距離: リンク表面のサンプル点から円柱までの符号付き距離の最小値を、サンプル間隔の分
  だけ小さく (安全側に) 見積もる (`human_obstacle_clearances`)。包含球同士の隙間が基準以上の
  組は計算を省く。

### 解の優先順位

1 つの x の窓の中では、コストの小さい候補から順に次を試す:

1. 事後検証 (上の 1・4) に落ちたら**完全に除外**する。
2. 事後検証を通った最初の候補を「フォールバック」として覚えておく。
3. 押し込み区間まで通ったら (上の 2・5)、その候補を**即座に採用**する。
4. 押し込み区間が解けない・検証に落ちたら、次にコストが小さい候補へ進む。

どの候補も押し込み区間に通らなければ、フォールバックを `post_process: null` のまま返す
(軌道計画は `post_process` が無い人を対象外にする)。
x の窓を含めた優先順位は、押し込み区間まで通り肩ヨーがねじれていない解がある最も狭い窓の解 →
押し込み区間まで通るがねじれた解 → 最初にフォールバックが得られた窓のフォールバック解 → 解なし
(`solved: false`)。

**肩ヨーのねじれ** (`solve_person_ik_side_by_side`): 押し込み区間まで通った解の肩ヨーの大きさが
**60°** (`TWISTED_SHOULDER_YAW_DEG`) を超えると、肘を外へ大きく回して手首もひねった枝
(接近で肘と掌が大きく回る) とみなし、すぐには採用せず次の窓も解く。次の窓でねじれずに
押し込み区間まで通ればそちらを採る。ねじれた解が見つかった後は無制限の窓 (負のマージン) へは
広げない。

### 対象外・失敗になる条件

| 条件 | 結果 |
|---|---|
| 掌 JSON の `offered_hand` が `null` | `target: false` (`no_offered_hand`)。IK を解かない |
| `offered_hand` はあるがその手の掌が無い | `target: false` (`no_palm`) |
| 全窓・全候補が未収束か事後検証で棄却 | `solved: false` |

## 3. 第2段: 押し込み区間 (曲線上の手先目標) + 視線

`solve_press_in`。hover 姿勢から、指先を押し出しながら掌へ詰める曲線上の手先目標を順に解く。
曲線は、指先方向の進み u (0 = hover 目標、1 = 最終目標) に対し

```
p(u) = 最終目標 − 指先方向 × 0.15 m × (1 − u) + 法線 × 0.04 m × (1 − u³)
```

(`press_in_target_position`、`PRESS_IN_CURVE_EXPONENT = 3` で詰めるのは終盤。向きは常に最終目標と
同じ)。u = k/8 の k = 1〜7 の 7 点 (`PRESS_IN_PATH_POINTS = 8`) は腕だけの IK
(`robot.inverse_kinematics`、40 反復、収束 0.01 m / 5°) で順に解き、最後の u = 1 (掌 − 1 cm) は
`solve_post_process` で腕と首を同時に解く。各点で台車を hover の位置から、指先方向の押し出しの
水平成分 × u だけ平行移動してから解く (`press_in_base_shift`、`PRESS_IN_BASE_RATIO = 1.0`、向きは
変えない。法線方向の詰めは腕が受け持つ)。途中の点の首は最終姿勢の角度にする。結果 (`post_process`) には
最終姿勢のほか、途中の点の関節角 `press_in_path` と台車 `press_in_base_path` が入る。
`--press-in-curve-exponent`・`--press-in-base-ratio`・`--press-in-slide`・`--press-in-lift`。

最後の点 (`solve_post_process`) は事後検証を通った候補の姿勢を初期値に、通常の
ヤコビアン法 IK (`robot.inverse_kinematics`) を 1 回呼び、腕と首の 2 タスクを
同時に解く。

| タスク | 目標 | マスク | 収束閾値 |
|---|---|---|---|
| 腕 (`{arm}arm_whole_body`) | 掌の位置 + 法線 × **-0.01 m** (掌へ 1 cm めり込む位置, `POST_PROCESS_TARGET_HOVER_OFFSET`)、姿勢は第1段で採用した向きそのもの | 位置・姿勢とも 6 自由度 | 0.01 m / 5° |
| 首 (`robot.head`) | カメラ光軸 (`camera_optical_coords` の +Z) を掌の位置へ向ける | 位置なし、姿勢 `'xy'` | 5° |

- 最大 40 反復。**干渉回避はしない** (自己干渉と手まわり以外の人体距離を 2 節の 5 で検証する)。
- 腕・首を同時に解けなければ (首の可動域で視線が届かないことが多い)、腕だけで押し込みを
  解き、首だけの視線 IK で向け直して、視線のずれが **15°** 未満
  (`POST_PROCESS_ARM_ONLY_GAZE_TOLERANCE`、カメラの縦の画角の半分 約 21° より内側) なら採用する
  (結果の `arm_only` が True)。同時 IK の失敗の過半は腕だけなら解け、合成 400 人 (seed 0) で
  横並びまで 44 → 48/62 人に増えた (2026-10-14)。押し込み直前の最終補正 (下) はこの代替を使わず、
  首を計画時の角度にした腕だけの解き直しを行う。
- **棄却条件: 腕が収束しない、腕だけで解いた場合に視線のずれが 15° 以上、または IK が例外を
  出す。** 押し込み区間では、途中の点のどれかが解けなくても棄却する。
- **脚のミミック関節を揃えて解き直す** (`settle_legs`):
  この IK は脚 (足首・膝) も動かすため、脚の平行リンクのミミック関節を主関節と食い違った
  角度で終える。実機に送る関節角は主関節だけなので、そのままだと手先は目標から IK の許容
  (10 mm) を超えて離れる (合成 140 件の保存した押し込み姿勢で 10.5 mm 超が 67 件、最大 149 mm)。
  成功後にミミックを主関節に合わせ (`sync_leg_mimics`)、脚を固定して腕・腰だけで同じ目標へ
  解き直す。解けなければ棄却。途中の点の IK も同じ。解き直すと 10.5 mm 超は 0 件 (最大 9.8 mm)、
  成功数・計算時間はほぼ変わらない (2026-10-15)。常に行う。
- 成功したら、IK の間に脚が動いて頭の位置がずれた分を、首だけの視線 IK で
  最大 3 回向け直す (`_reaim_gaze`)。

### 押し込み直前の最終補正 (実機のみ)

`refine_post_process`。実機が hover 目標に着いた後、カメラで掌を検出し直し、
hover 姿勢を初期値にして押し込み区間 (`solve_press_in`、上と同じ曲線・同じ台車の平行移動) を
解き直す。検出した掌は台車が hover 目標にいる前提で計画時の座標系へ移すので、台車のスリップと
手の動きの両方を腕で吸収する。

| 条件 | 結果 (`reason`) |
|---|---|
| 手を検出できない | 計画どおりの押し込み (`no_hand`) |
| 押し込み目標の変化が 0.10 m を超える、または 30° を超える | 計画どおりの押し込み (`too_large`) |
| 腕・首とも収束 | 補正した押し込み (`ok`) |
| 首が収束しない | 首を計画時の押し込み姿勢の角度に固定し、腕だけで解き直す (`ok_arm_only`) |
| 腕だけでも収束しない | 計画どおりの押し込み (`ik_failed`) |

手の検出 (実機ノード `_select_offered_hand`): hover 到達後に最大 3 フレーム・1.5 秒
(`PRESS_IN_REFINE_FRAMES`/`_TIMEOUT`) 集め、MediaPipe Hands の候補のうち score が 0.8 未満
(`PRESS_IN_REFINE_MIN_HAND_SCORE`)・掌の法線が計画時から 45° 超 (`_MAX_NORMAL_ANGLE_DEG`)・
計画時の掌から 0.15 m 超 (`_MAX_HAND_DISTANCE`) の手は除く。解き直した押し込みの検証は行わない (6 節)。
`--no-press-in-refine` で無効にできる。

## 4. 軌道計画

`plan_person_motion`。対象は `target: true` かつ `solved: true` で、押し込み区間
(`post_process`) まで解けている人物だけ。
終点は第1段の hover 姿勢 (押し込み区間は経路として計画せず、2 節の 5 で検証済み)。

### 接近開始位置の候補と優先順位

1. 角度 0 の候補を最初に試す。人の手を中心とする半径 (手から最終台車位置
   までの距離 + **0.3 m**, `DEFAULT_APPROACH_DISTANCE`) の円周上で、初期位置からの
   直進 (lead-in) が公転+自転の螺旋の接線になる位置 (`orbit_tangent_start`)。
   向きのずれが 3° 以内にそろう位置が無ければ、手から初期位置の方向
   (`orbit_base_start`)。0.2 m では、人の背後から回り込む配置で接近開始位置が人の真横
   (立ち位置から約 0.65 m) に来て台車が脛に触れる人がいたため 0.3 m。
2. 角度 0 で lead-in か軌道 (最適化込み) が検証を通らなかったときだけ、
   角度 0 の方向を ±30° 刻みで ±120° まで回した 8 候補を、台車の経路長
   (初期位置→候補→最終位置) が短い順に試す。ここでは**最適化なし**で lead-in と
   軌道の両方が通った最初の候補を採る。
3. それも無く、角度 0 の lead-in が通らなかった場合は、lead-in が通った
   最短の候補で最適化まで行う。
4. どれも通らなければ角度 0 の結果を返す (`verified: false` のまま)。

公転の向きは、手から見て人の立ち位置の方位を通らない側 (`orbit_sweep`)。
自転 (台車の向き) は最短の向きに回すが、そうすると螺旋の途中で台車の正面から見た
人の立ち位置か掌の方位が **110°** (`ORBIT_SPIN_MAX_BEARING`) を超えるときは、逆向き
(1 周ずらした向き) の方が方位の最大が小さければ逆向きに回す (`_spin_toward_human`)。
首ヨーの可動域は約 ±120° で、人が背中側を通ると首で追えずカメラの視界から外れるため
(実機 10/21 試行 6: 左手の人に対して時計回りに 132° 回り、掌が真後ろを通って首ヨーが
上限に張り付いた)。向かい合って始めると、人の左手なら反時計回り、右手なら時計回り
(回る途中で正面が人の方を通る) になる。
公転の中心は掌の水平位置 (`palm_position`)。初期位置が既に半径以内なら、後退せず
初期位置から計画する (`MIN_APPROACH_DISTANCE`)。

### lead-in (初期位置 → 接近開始位置)

- その場回転 (10° 刻み) → 直進 (0.1 m 刻み)。最適化はしない。
- 台車が人の立ち位置から **1.0 m 以内** (`LEAD_IN_CHECK_RADIUS`) の
  waypoint だけを、接近軌道と同じ条件 (下の「事後検証」。ただし差し出さない手の指先と台車の
  箱の距離は含めない) で検証する。

### 軌道の作り方と優先順位 (`_plan_from_start`)

20 waypoint (`DEFAULT_N_WAYPOINTS`)、始点は両腕を下ろした姿勢 (`arms_down_angles`)
+ 接近開始位置、終点は hover 姿勢 + hover の台車位置。次の順に作り、**最初に
検証を通ったものを採用**する。

| 順 | 種類 (`kind`) | 作り方 |
|---|---|---|
| 1 | `linear` | 関節は線形補間、台車は螺旋 (`orbit_base_path`) |
| 2 | `optimized` | 1 を warm start に jaxls で最適化 |

手先空間での最後の近づき方は押し込み区間 (hover から滑らせて押し込む) が決めるので、
接近区間の腕は線形補間で hover へ上げるだけにしている (手は hover へ下から入る)。

以前は 1 の前に `pretouch` (hover の手先を台車の方へ水平に 0.25 m 引いた姿勢を経由し、
最後の 25% は台車を止めて hover へ) を試していたが、2026-10-28 に削除した。
10/15 に引き戻しを水平・脚固定にして以降、その IK はほぼ解けず
(合成 67 人の比較セットで解けたのは 60 人中 12、採用されたのは 2 人)、無くしても軌道 60/67・
横並び 58 (100% 56) は同じで、接近の計画時間は平均 0.096 → 0.074 秒/人になった。
採用されていた 2 人は、hover へ水平に入る動きが下から入る動きに変わる。

jaxls の軌道最適化 (`build_problem`):

| 項 | 扱い | 重み・パラメータ |
|---|---|---|
| 速度 (滑らかさ) | コスト | 1.0 |
| 加速度 | コスト | 1.0 |
| 関節可動域 | 制約 | 0 節の制限のみ |
| 台車の位置・向き | 制約なし | — |
| ロボット×人体の干渉 | ソフトなコスト | 重み 100、効き始め **0.06 m** (`DEFAULT_COLLISION_ACTIVATION_DISTANCE`、円柱は太らせない。差し出された手まわりだけ 0 節の通り掌・指を除き前腕を 2 cm 相当に細らせる) |
| 自己干渉 | ソフトなコスト | 重み 100、効き始め 0.02 m |
| 始点・終点 | 固定 (等式制約) | — |

- 干渉は `add_collision_cost(..., as_constraint=True)` で渡しているが、jaxls のソルバーは
  制約ではなく「効き始めより近づいた分」に比例するソフトなコストとして扱う。
- 最大 60 反復 (`DEFAULT_MAX_ITERATIONS`)。解き直しはしない (warm start を揺らしての再試行は、
  合成 67 人・400 人とも 0 人しか救えなかったため削除)。

### 事後検証と棄却条件

- lead-in (1 m 以内) と全 waypoint (hover を含む) で、IK の事後検証と同じ 2 つを見る:
  - 自己干渉の組の貫通 (許容 0 mm、`verify_waypoints`)。全 waypoint では差し出さない手の指先と台車の箱の
    距離 (`other_hand_base_clearance`) も含める。
  - 人体 (全身) から **5 cm** 以上 (指ありモデル、`verify_human_clearance`、
    `phm.DEFAULT_HUMAN_CLEARANCE`)。ただし差し出された手まわりだけ **2 cm**。hover の IK の
    6 cm より 1 cm 緩い (下の「接近の検証を 5 cm に」)。hover の事後検証も同じ 5 cm。
- **`verified` の条件: 上の 2 つを全 waypoint で満たす** (`motion_passes`)。結果の
  `waypoint_min_distances` は自己干渉の最小距離、`waypoint_human_clearance_margins`/
  `lead_in_human_clearance_margins` は人体との距離から基準 (5 cm、手まわりは 2 cm) を引いた
  余裕 (基準より遠い組は計算を省くので、余裕 0 は「基準以上」の意味)。

### 接近の検証を 5 cm に (2026-10-14)

hover の IK は人体から 6 cm で解くので、hover は 6 cm ちょうど付近に来る。接近の検証も
6 cm だと、経路が差し出した掌・前腕へ数 mm 入るだけで落ちていた (実機 2026-10-13 の試行
1・2・9 は 1〜8 mm 不足)。経路の検証だけ 5 cm に緩めた (hover の IK・軌道最適化の効き始め・
IK 段階の hover の事後検証はこの時点では 6 cm のまま (10/29 に 5 cm、下)。軌道計画で差し出さない腕を差し替えた後の再検証
(`handshake_with_other_arm_posture`) は `phm.DEFAULT_HUMAN_CLEARANCE` を使うので 5 cm)。
保存した実機 10/13 の 13 試行を
解き直すと、6 cm で 8/13、5 cm で 11/13 が通った。5 cm でも残る 2 試行は距離と関係ない
(試行 11 は自己干渉 -6 mm、試行 12 は接近の途中で差し出した手まで 1.1 cm)。
差し出された手まわりを 2 cm にしたのはその後の hover の変更 (hover が掌から約 2 cm になった) による。

2026-10-29 に IK 段階の hover の事後検証 (`DEFAULT_HOVER_HUMAN_CLEARANCE`) も 5 cm にして、
検証の距離を全段階で揃えた (hover の IK のペナルティと軌道最適化の効き始めは 6 cm のまま)。
合成 400 人 (seed 0) は後処理まで 60・軌道 60 で変わらず、選ばれた hover の関節角も 60 人とも
同じ。横並びは 59 → 58/60 だが、減った human_232 は hover 姿勢が同じで探索の時間の上限による
揺れ。保存した実機 37 試行 (10/13・10/15・10/22) は横並びまで 11 で同じ、1 試行
(10/22 16:20:35) が ik_fail → no_press に進んだだけ。IK の時間は合成で 0.476 → 0.471 秒/人、
実機の解き直しは平均 1.76 → 1.68 秒/試行 (差は横並びの計画時間の揺れ)。

- 軌道が通らず、その原因に指先と台車の干渉が含まれるときは、差し出さない腕を
  `OTHER_ARM_POSTURES_DEG` の 1 段曲げた姿勢に差し替えて計画し直す
  (`handshake_with_other_arm_posture`: hover と差し替え後の姿勢を自己干渉と人体 (5 cm、手まわり
  2 cm) で検証し直し、押し込み区間の途中の点は自己干渉だけ検証する)。通れば IK 結果もその姿勢に
  書き換える (`other_arm_posture_replanned`)。
- どの作り方でも通らなければ、自己干渉と人体との距離のうち足りない方の余裕が
  最も大きい軌道を `verified: false` のまま返す (`motion_margin`)。結果の
  `candidates_tried` に試した候補ごとの合否を残す。
- 実機 (`run_camera_pipeline_test.py --auto-execute`) は `verified` と
  `lead_in_verified` の両方が真で、横並び移動を行う設定 (既定) なら横並び移動も解けている
  ときだけ動かす (`_execution_verified`)。

### 台車の移動範囲

軌道計画では、台車の経路が通ってよい範囲を**どこにも制限していない**。
第1段の `base_limits` が縛るのは終点 (最終台車位置) だけ。経路の避け方は人体との
干渉検証だけで決まり、壁・家具などの環境の障害物は考慮しない。実機 (`--auto-execute`)
も costmap を使わない相対移動 (`go_pos_unsafe` 相当) で送る。

### 検証の後で書き換えるもの (再検証しない)

- 接近区間の後半 50% (`HEAD_GAZE_BLEND_START`) で、首の角度を押し込み姿勢の
  値へ線形補間する (`blend_head_to_post_process`)。

## 5. 押し込み後の横並び移動

`sbs.plan_transition`。押し込み (掌を合わせた姿勢、3 節) の後、**つないだ手を人の体の
横へ下ろしながら**、ロボットも人と横並びの位置・向きへ移る区間。台車だけを後ろへ
下げる動きにはしない。合成データ (`run_pipeline_test.py --plan-motion
--side-by-side-transition`) と実機ノード (常に有効)
の両方で計画する。どちらも接近の軌道が `verified` の人だけ計画する。

計画は 2 段 (合成も実機ノードと同じ、2026-10-23 から):
1. **動く前に確保する計画** (`plan_transition(approach=False)`、結果の `transition`):
   寄せ (段階 2) は解かず、横並びまで進んだ最初の解で止める。差し出し 1 回に対する計画全体
   (IK → 接近の軌道計画 → この計画) の締め切り **5 秒** (`spik.PLAN_TIME_LIMIT`、
   `--plan-time-limit`) の残りで打ち切る。
2. **動作中に裏で解く計画** (`refine_transition`、`transition_refined`): 確保した計画からの
   寄せと、残りの掌の向き。5 秒の締め切りはかからず、残りの掌の向きの探索に **10 秒**
   (`REFINE_TIME_LIMIT`) の上限。実行するのは確保した計画以上に進めた方
   (`transition_executed`)。実機ノードは横並び移動を始める時点で終わっていなければ止める
   (下の「計画時間の短縮と 5 秒の締め切り」)。

### 人の腕のモデル

押し込み目標から人の掌を逆算し (`human_palm_from_press`)、人の腕を `HumanArm` で表す。
肩は動かさず、手首から先は押し込み時の手に対して剛体。waypoint ごとに次の目安を記録し、
ビューアはこれで人の腕 (SMPL と干渉判定の円柱) をロボットの手に追従させる (肘は
記録した肘の側)。

| 目安 | 扱い |
|---|---|
| 到達率 (肩–手首 / 腕の長さ) | **1 を超えたらその手前で止める** |
| 人の手をロボットの手に固定したときの手首の角度 (掌屈・背屈、撓屈・尺屈。下の「人の手首」) | **目安を超える移動先は握りの向きを変えて解き直すか捨て、経路はその手前で止める** (`HUMAN_WRIST_CHECK = 'hand_fixed'`) |
| 腕を下ろす途中の人の肩 (屈曲・伸展、外転・内転、回旋)・肘・前腕 (回内・回外) | **目安を超える下ろし方は IK の前に外す** (`HUMAN_ARM_CHECK`、`HumanArm.lowering_problem`) |
| 上腕の真下からの角度、肘の曲げ、手首の曲げ (前腕と手のなす角、`HumanArm` の剛体の手)、前腕のひねり (押し込み時からの変化) | 表示のみ。肘は目安 120° を超えたら `(!)` を付ける |

目安はすべて LUBA (Kee & Karwowski 2001) の最後の段階の始まりで、根拠は
[human_joint_angle_references.md](human_joint_angle_references.md) (2026-10-27)。

ログ・表示の「人の腕の最大」は**押し込み時 (s=0) を除いた** waypoint (横並び・寄せ) の最大
(以前は押し込み時の推定を含めていて、手首の曲げの最大はほぼ押し込み時の値で決まっていた)。

**人の手首 (2026-10-22)**: `HumanArm` は掌を計画どおり動かすだけで、握りの向き (掌の法線まわり、
移動先・経路で自由) が変わっても人の手は回らない。実際は人の手がロボットの手について回るので、
その分は人の手首の撓屈・尺屈になる。そこで人の手の向きを、ロボットの手先の向きから押し込み時の
握りの向き `turn_before` で逆算し (`hand_on_robot`、`human_palm_from_press` と同じ)、
`HumanArm` の前腕 (肘 → 手首) に対する手首の角度を `human_wrist_angles` で分ける
(指先が前腕の向きを 0°、右手は手先の指先 × 法線が親指側、左手は小指側。合成の手の landmark で確認)。

| 成分 | 目安 (`HUMAN_WRIST_*_MAX_DEG`) | 根拠 |
|---|---|---|
| 撓屈 (親指側) | 30° | LUBA の最後の段階の始まり |
| 尺屈 (小指側) | 20° | 同上 |
| 掌屈・背屈 | 60°・45° | 同上 |
| 前腕のひねり | 見ない | 2026-10-27 から絶対的な回内 70°・回外 90° (腕の目安) だけで判定。ロボットが人の掌に合わせているかぎり同じひねりなので (`--transition-twist-limit` で押し込み時からの変化も見られる、以前は 80°) |

押し込み時の推定 (骨格の肘・手首と掌の向き) がすでに目安を超えている成分は、押し込み時の値 + 5°
(`HUMAN_WRIST_PRESS_SLACK_DEG`) までの超過を、`HumanArm` が手首の曲げを戻すのと同じく腕を下ろす
割合 s に比例して減らしながら許す (s=1 で目安どおり。寄せは s=1)。押し込み時の推定は誤差が大きく
(10/21 試行 6 は尺屈 50°・背屈 39°)、許さないと押し込み直後で止まるため。
簡易版の `'turn_cap'` (握りの向きの押し込み時からの変化を 20° 以内) とも比べ、下の結果で
`'hand_fixed'` にした。

**手の下ろし方は人の腕で決める** (ロボットがしゃがまずに済む高さではなく、人が肩から
腕を下ろせるか)。下ろした腕 (`HumanArm.lowering`) は、上腕を真下から前へ
`LOWERED_ARM_DEG_GROUPS` の角度に上げ、外へ **25°** (`LOWERED_ARM_ABDUCTION_DEG`、
胴体の干渉円柱の外に手を出す。10° だと低い目標が検証でほぼ全部落ちる。25° で
移動先・経路が通らない人は **40°** (`LOWERED_ARM_WIDE_ABDUCTION_DEG`) も試す) 開き、肘を **15°** (`LOWERED_ELBOW_FLEX_DEG`) 曲げた形。腕は「上腕の向きと肘の蝶番軸の組」を
slerp、肘の曲げとひねりを線形に補間するので (`lowering_pose`)、手は肩を中心に円弧で下りる。
(以前の、上腕を真下に置いて前腕だけを 20/50/80° 上げる形は、コストがロボットのしゃがみ量しか
見ていないため全員が 80° (前腕が水平) を選び、人から見ると手を下ろしていなかったので使わない。)

**下ろした掌の向き** (`facing_variants`): 次の順に試し、その向きで移動先・経路が横並びまで
通らなければ次の向きへ進む (ロボット側=外向きは使わない)。

| 押し込み時の人の掌 | 試す順 (`LOWERED_FACING_ORDER` / `_PALM_UP`) |
|---|---|
| 下・横向き (掌の法線の上向き成分 < 0、`PALM_UP_NORMAL_Z`) | `natural` → 後ろ → 人側 → 前 |
| 上向き (同 ≥ 0) | 前 → 後ろ → `natural` → 人側 |

- `natural` が先なのは、前腕をひねらず人の手首に負担がないため (10/19 の実機で、後ろ向きに
  127°・90° ひねる姿勢を使い人の手首がねじれた)。次に後ろ向きを試す。後ろ向きは、ロボットが
  人の手の後ろから肘を伸ばして手を合わせられ、肘を曲げずに済み干渉しにくい。掌が上向きの人は、
  後ろ向きへ回すと前腕を 150° 前後ひねる (回内) ので前向きを先にする (どちらもひねりが
  下記の上限を超えれば使わない)。
- `natural` は前腕をひねらず、腕を下ろす回転だけで手を動かした向き (手は親指側の軸まわりに
  回って指先が下を向く)。終点の掌の法線が外向き成分 0.3 (`LOWERED_NATURAL_MAX_OUTWARD`)・
  上下成分 0.5 (`LOWERED_NATURAL_MAX_VERTICAL`) を超えるときは使わない。
- 前腕は、絶対的な回内 70°・回外 90° を超える向きを試さない (上の腕の目安。2026-10-27 までは
  押し込み時からのひねり 80° (`LOWERED_TWIST_MAX_DEG`) で外していた、今は既定 None)。
- 前腕のひねりは腕を下ろす動きの **50%** (`LOWERED_TWIST_START`) から始める (同時にひねると
  前に出した前腕のまわりで手が回り親指が上を向く)。押し込み時の手首の曲げは、腕を下ろす
  間に線形に戻し、下ろしきると指先が前腕の向きになる (`LOWERED_WRIST_STRAIGHTEN = 1.0`)。

### 移動先 (`solve_goal_candidates`)

- 1 節と同じ形のバッチ IK (目標 3 つ = 下ろした腕 3 つ、初期値 **256**
  (`GOAL_ATTEMPTS_PER_POSE`、1 節の半分)、台車も動かす、干渉回避あり)。人の
  差し出した手・前腕・上腕は手を合わせているので障害物から外し、代わりに
  **下ろした後の上腕** (目標 3 つ分) をその枠に置く。干渉ペアは押し込みの
  `collision_pairs.json` に次を足す (`_transition_pairs`):
  - 差し出す腕の前腕・肘 × 下ろした上腕・差し出した側の胴体 (`{手}Shoulder-{手}Hip`)
  - 自己干渉: 差し出さない腕の前腕・手 × 腰 (`hip_sphere_link`/`waist_link`)、
    差し出す腕の前腕・手・肘 × 腰・胴 (`waist_link`/`body_link`)

  移動先の検証に落ちる候補は、ほぼこの組 (押し込みの IK には無い) だった。
  - **障害物の共有 (2026-10-22 に対処)**: バッチ IK の障害物は 3 つの目標で共有されるので、
    3 つの角度を 1 バッチにすると、各目標が下ろした上腕 3 本すべてを避ける。10/22 実機試行 2
    は 0/15/30° の組 (脇 25°) が全部解けず、30°・脇 40° で掌が 0.99 m までしか下がらなかった
    (0° だけで解くと 0.85 m)。そこで上腕の角度ごとに 3 つとも同じ下ろし方の目標で解く
    (`LOWERED_ARM_BATCH = 'per_angle'`、初期値が実質 3 倍。下の「手を下ろす・離れて戻らない」)。
    2026-10-23 から、3 つの目標には同じ上腕の角度・脇の開きで**掌の向きだけが違う**下ろし方を
    入れてまとめて解く (`GOAL_BUNDLE_FACINGS`。上腕が同じなので低い下ろし方が解けなくなる
    問題は起きない。下の「計画時間の短縮と 5 秒の締め切り」)。
  - 検証 (5 cm・自己干渉 0 mm) は IK のペナルティとは別に行う。足したのは IK のソフトな
    ペナルティだけで、最終的に通るかは検証で決まる。
  人の正面方向を +x に回した座標系で解く。
- **人が腕を低く下ろせる方を優先する**: 上腕の角度の組 (`LOWERED_ARM_DEG_GROUPS`) を
  **0/15/30° → 45/60/75°** の順に解き、横並びまで (100%) 進めた組で止める。同じ上腕の
  角度の組の中では、`'per_angle'` (既定) は低い角度から 1 つずつ、同じ角度の中では掌の向き
  (上の順) を脇の開きより優先し、向きごとに脇 25° → 40° の順に試す (`'group'` は組の 3 角度を
  1 バッチ)。組の中では腕の低い目標の解を先に、同じ目標の中ではコストの安い順に、目標 1 つ
  あたり検証まで 8 候補 (`MAX_GOAL_CHECKS`、手を低く下ろす目標は人の胴体に近く検証に落ちる候補が
  数百続くことがあるため)・経路まで 2 候補 (`MAX_GOAL_CANDIDATES`) を試す。
- 台車の窓: 前後は人の立ち位置 **±0.05 m** (`GOAL_X_MARGIN`。以前は
  ±0.05 → 0.15 → 0.3 → 0.5 m と広げていたが、横並びまで進めた人は全員 ±0.05 m で
  解けていた)、左右は**差し出した手の左右** (人の正面を +x とすると左手は +y、右手は −y。
  差し出した手首の位置で決めると、体の中心線をまたぐ人で押し込み時の台車と反対側になり
  解けなくなる)、向きは人の正面 ±30°。
- **腕の解の枝を押し込みと同じに限る**: 差し出す腕の肩ヨー・手首ヨーが押し込み姿勢から
  **±60°** (`GOAL_BRANCH_JOINT_RANGE_DEG`) を超える解は捨てる。押し込みは腕を前に出した
  形で、腕を体の横に垂らして肩・手首を可動域の端までひねった形 (膝を伸ばしたまま手を
  下ろせる) とは別の枝。手を合わせたまま一方から他方へは移れず (途中で手が大きく回り、
  人の手首がねじれる)、経路が前に出した腕のまま膝を曲げて手を下げ、終点の手前で
  肩・手首が 120° 以上飛んで止まっていた。
  - 捨てるのはバッチ IK の後。skrobot のバッチ IK はソルバーを作ったときの関節の
    可動域をキャッシュし、呼び出しごとに上書きされるのは台車の仮想関節だけなので、
    呼び出しの前に可動域を絞っても効かない。
- **握りの向き (人とロボットの指先のなす角) は自由**: 手先の +Y (掌の法線) まわりの
  回転だけを拘束しない (`rotation_mask = [1, 0, 1]`、`GOAL_FREE_TURN`)。押し込みまでは
  握りの向きを決めて合わせ、そこから手を下ろしやすい向きへ少しずつ回す。固定 (0°、だめなら
  ±90°) と比べて成功数は同じで、移動先の knee がほとんど曲がらなくなり (中央値 −45° → −19°)、
  時間も短くなる。`GOAL_FREE_TURN = False` なら 0° で解き、解が 1 つも無いときだけ ±90° も試す
  (`GOAL_TURN_DEG_GROUPS`)。
  - 解いた移動先で人の手首 (上の「人の手首」) が目安を超えるときは、目安に収まる握りの向きのうち
    一番近いもの (端から 5° 内側、`WRIST_TURN_MARGIN_DEG`、`wrist_ok_turn`) に固定して押し込み
    IK を解き直し (`fix_goal_wrist`)、それでも超えれば捨てる。寄せ (段階 2) の移動先も同じ。
- コスト (同じ目標の中での順):

  ```
  cost = 曲げ量 (2 節と同じ)
       + 100 × |前方ずれ [m]|            (GOAL_FRONT_OFFSET_WEIGHT)
       + 30 × |向きのずれ [rad]|         (GOAL_FACING_YAW_WEIGHT)
       + 10 × |ankle + knee| [rad]       (GOAL_LEG_OFFSET_WEIGHT, 上体の前後ずれ)
       + 0 × (|ankle| + |knee|) [rad]    (GOAL_CROUCH_WEIGHT, しゃがみ量。以前は 30 で、沈みは罰しない)
       + 1000 × max(0, waist_p [rad])²   (GOAL_BOW_WEIGHT, 腰の前傾 = お辞儀)
       + 30 × 手首ヨー・ロールの端への近さ (GOAL_WRIST_WEIGHT, 可動域の 70% を超えた分を
                                          30% を 1 として 2 乗)
       + 30 × (1 + 指先の鉛直成分)       (GOAL_ROBOT_FINGER_DOWN_WEIGHT, 指先が下を向いていない分)
       + 10 × (|手首ロール| + |手首ヨー|) [rad] (GOAL_WRIST_BEND_WEIGHT, 手首の曲げ)
  ```

  ロボットの指先の向きは手先 (`{l,r}arm_end_coords`) の **+Z** (`finger_direction`。
  指ありモデルの指の表面点の向きで確かめたもので、`_correct_grasp_frame` の +X ではない)。
  指先の鉛直成分が **-0.5** 以下 (`GOAL_FINGER_DOWN_MAX_Z`) の「指先が下を向く」候補が
  1 つでもあれば、それ以外の候補は捨てる (コストだけでは腕を低く下ろせる上向きの解が先に
  選ばれ、指先が上を向いたまま横並びになるため)。

- 各候補は、首も含めて押し込みと同じ IK (3 節、視線は人の顔 = 鼻 (無ければ両耳の中点、
  それも無ければ人の正面 3 m 先・目の高さの点) へ、`forward_gaze_point`) で
  解き直す。指先がまだ上を向いていれば (鉛直成分 > -0.5)、握りの向きを指先が一番下を
  向く角度 (`down_turn_deg`) に固定して解き直し、指先が下がったときだけ採る。最後に首だけの
  視線 IK (`_aim_head`、今の首の角度と 0° の両方から解いて視線のずれの小さい方) で顔へ
  向け直し、下の「検証」を通ったものだけ経路を作る。
- 経路を計画する前に、台車の経路で車輪が人の脚に近づく候補を外す
  (`TransitionChecker.check_base_path`、安く判定できるので `MAX_GOAL_CHECKS` には数えない)。
  台車を start から goal まで補間する間の、車輪と人の脚などの距離 (人の腕は動くので除く) が
  5 cm 未満の候補を外す。

### 経路 (`plan_path`)

- 台車・人の腕 (肩まわりに下ろす、`lowering_pose`) を補間し、各 waypoint で腕の IK
  (3 節と同じ押し込み目標) を、直前の解を移動先の姿勢へ 1 区間分寄せた初期値 → 直前の解の
  順に解き進める。脚は押し込み時から移動先の値へ均等に近づけた角度に固定し、解けなければ
  脚も動かして解く。
  - 腕を下ろす途中で、上腕を外へ **10°** 膨らませる (`LOWERED_BULGE_DEG`。両端の姿勢は
    変えない。手を合わせたまま腰の横へ下ろすと、ロボットの前腕が人の胴体・太ももに近づいて
    止まるため)。実機 10/13 の 13 人で 0 → 10 → 20° は 100% が 6 → 7 → 6 人、上腕の
    中央値 45 → 40 → 34°。合成 21 人は 0・10° で 21/21 (ほぼ同じ)、20° は 17/21。
  - 台車は人の立ち位置を中心に、距離と方位を線形に補間して回り込む (`BasePath`)。
    直線 (弦) だと人の足元の近くを通り、車輪が人のすねに近づくため。
    yaw は線形に補間する。
  - 握りの向きは押し込み時の値から移動先の解の値へ補間して固定する。
  - 首は IK で解かず、押し込み時から移動先 (顔を見る姿勢) の角度へ関節角で線形に
    補間する (視線の IK だと台車の向きに合わせて首が細かく往復するため)。
  - 上体が傾いて差し出さない手が台車前方の箱から 2 cm 未満に近づいたら、差し出さない腕を
    押し込みの計画と同じ姿勢の候補 (`OTHER_ARM_POSTURES_DEG`) に差し替える (直前より曲げの
    小さい候補には戻さない)。差し出さない腕の肩ピッチ・肘と首は、関節角の飛びの判定から
    外す。
- **掌が離れないこと**: 脚も動かして解く IK (`free_legs`) は、脚のミミック
  関節 (平行リンク) を主関節と食い違った角度で終える。実機に送る関節角は主関節だけで、
  ミミックは主関節から決まるので、そのままだと掌が離れる (実機 13 人の経路 661
  waypoint のうち 114 で IK の許容 10 mm を超え、90% 点 23 mm・最大 113 mm)。IK の後に
  ミミックを主関節に合わせ、脚を固定して腕だけ解き直し (`_press_ik`、`_sync_leg_mimics`)、
  解けなければその waypoint は失敗とする。修正後は全 waypoint で掌の位置ずれが
  最大 9.9 mm (許容内)、法線ずれ最大 4°。`_place` も関節角を入れた直後にミミックを合わせる。
- waypoint の数: 台車・掌 (掌は円弧に沿った道のり) が 1 区間 **10 cm・10°** 以内 (`MAX_STEP`/`MAX_ANGLE_STEP`)、
  かつ押し込み姿勢と移動先の関節角の差が 1 区間 **20°** 以内 (`PLANNED_JOINT_STEP`)
  になる数。細かく刻むと、IK が腰・手首を waypoint ごとにジグザグに収束させ、毎区間が停止・
  発進になって加速度制限で実機の動作時間が延びるため (5 cm・5°・15° 刻みだった頃から粗くして、
  合成 42 人で区間数 22 → 11、動作時間 平均 7.5 → 4.7 秒、横並び成立は 42/42 で変わらない)。
- **止める条件 (その手前までを使う)**: 人の腕が届かない、IK が解けない、隣の waypoint
  から関節角が **20°** (`MAX_JOINT_STEP`) を超えて変わる (IK が別の解へ飛んだとみなす。
  首と差し出さない腕は見ない)、下の検証に通らない、人の手首が目安を超える (`wrist_problem`)。
  各 waypoint の `human_arm` に、腕を下ろす割合 `s` と手首の角度 `robot_hand_wrist` を記録する。
- 移動先の **30%** (`MIN_FRACTION`) まで進めなければ横並び移動はしない (`verified: false`)。

### 検証 (`TransitionChecker`)

移動先と全 waypoint で、自己干渉の貫通 (許容 0 mm) と人体から **5 cm** 以上
(`TRANSITION_HUMAN_CLEARANCE`、台車の経路の車輪と脚も同じ。4 節の事後検証と同じ
モデルで、差し出された手まわりにも 2 cm ではなく 5 cm を使う)。hover の IK の 6 cm より
1 cm 緩め、接近の検証と同じ値 (下の「人体との距離を 5 cm に」)。人の差し出した腕は waypoint ごとに動かした骨格で見る。
ロボットの差し出す腕の肘から先と、人の差し出した手・前腕の組は手を合わせているので
見ない。代わりに、肘・前腕・手首と人の前腕・手の甲は 2 cm 離す (押し込み時に近い分は許す。下の
「押し込み時と横並び移動の前腕の重なり」、`HUMAN_FOREARM_OBSTACLE`)。
人体の円柱 (skrobot の `Cylinder`) は、メッシュ (collision_mesh・visual_mesh・
連結メッシュ) を**初めて読まれたときに作る** (遅延生成、scikit-robot の `Link` の
`lazy_mesh_factory`)。距離を測るだけの用途は読まないので作られず、ビューア・バッチ IK・
軌道最適化は読むときに従来と同じメッシュが作られる (`human_body_obstacles` 1 人分は
約 9.3 → 1.3 ms)。

### 手を下ろす・離れて戻らない (2026-10-22)

10/22 実機試行 2 (`data/bags/camera_pipeline_2026-10-22-16-19-15.bag`) で、横並び移動のときに
ロボットが人から離れてからまた近づき、手も下がりきらなかった (掌 1.07 → 0.99 m)。実行したのは
裏の計画 (寄せあり) で、段階 1 の移動先が人の横 1.08 m (押し込み時 0.75 m)、寄せで 0.65 m へ
戻っていた。段階 1 の移動先は腕の解の枝を押し込み時と同じに限る (肩ヨー・手首ヨー ±60°) ので、
人の近くの解がほとんど無く、寄せ (±100°) で枝を変えて戻る。

### 押し込み時と横並び移動の前腕の重なり (2026-10-22)

上の「人の手首」だけでは、ロボットの前腕が人の前腕に重なるのを防げない (10/21 試行 6 は押し込みの
時点で前腕の円柱に入っていて、横並び移動で -4.5 cm まで入る)。距離はロボットの差し出す腕の肘・
前腕・手首 (`spik.FOREARM_CHECK_LINKS`、手は除く) の表面から、人の前腕 (肘 → 手首、半径 4 cm) と
手の甲 (下の「人の手首と前腕」の円柱) の表面まで (`spik.forearm_obstacles`)。

1. **押し込み区間** (`spik.PRESS_IN_FOREARM_CLEARANCE = 0.02`、`--press-in-forearm-clearance`):
   押し込み区間の各点 (`pick_verified_candidate` の `_press_in_path_rejected`) でこの距離が 2 cm
   未満の候補を捨てる。それまで押し込み区間は手まわり (掌・指・同じ側の前腕) を見ていなかった
   (hover は手まわり 2 cm で見ている)。
2. **横並び移動** (`HUMAN_FOREARM_OBSTACLE = True`、`FOREARM_PRESS_ALLOWANCE = True`): 移動先の
   バッチ IK と、移動先・経路の全 waypoint の検証で 2 cm 離す。押し込み時にすでに 2 cm より近い分
   (押し込み時の距離 - 0.5 cm、`FOREARM_PRESS_SLACK`) は、腕を下ろす割合 s に比例して減らしながら
   許す (`TransitionChecker.forearm_limits`、s=1 の移動先と寄せは 2 cm)。押し込み時より深く入る
   経路、途中で近づく経路は止まる。

### 人の手首と前腕 (2026-10-22)

10/21 の実機 (試行 6) で、横並び移動中に人が掌をロボットに合わせ続けると、ロボットの前腕を

障害物から外している、(b) 握りの向きの変化 (試行 6 は -90 → -129°) が人の手首の撓屈・尺屈に
なるのを評価していない。対策を 2 つ実装して比べた。

1. **人の前腕・手の甲を障害物にする** (`HUMAN_FOREARM_OBSTACLE`、この時点では無効にした。

   手首、半径 4 cm) と手の甲 (手首を掌の面に移した点 → 掌 + 指先 8 cm を、掌の面から甲側へ
   2 cm ずらした半径 2 cm の円柱。掌の接触面は含まない、`forearm_obstacles`) を、ロボットの
   差し出す腕の肘・前腕・手首 (`{arm}_elbow_link`/`_forearm_link`/`_hand_yaw_link`) から

   `HumanArm` の姿勢で見る。ロボットの手と人の手の組は今までどおり見ない。

### 計画時間の短縮と 5 秒の締め切り (2026-10-23)

**内訳** (HEAD 984feca、関数ごとの時間を測った): 合成 (当時は寄せまで同期で解いていた) は
1 人 平均 7.3 秒のうち移動先のバッチ IK が 67% (寄せ 41%・段階 1 26%、1 回約 0.2 秒、1 人
あたり寄せ 14.5 回・段階 1 9.2 回)。時間の上限 10 秒に達した 17 人は、寄せ後の横の距離が
`APPROACH_STOP_LATERAL` 以下にならず、掌の向き 8 つを順に段階 1 + 寄せで解き続けていた
(1 人 30〜37 回、半分は候補 0)。実機ログ (押し込み姿勢から 31 試行) の確保する計画は
バッチ IK 51%・押し込み IK 25%・`_aim_head` 11%・`fix_goal_wrist` 8%、裏の計画は
バッチ IK 64%。

**バッチ IK の時間は初期値の数ではなく呼び出しの回数で決まる**: 実データの呼び出しで、
384 → 16 レーンで 0.20 → 0.17 秒、1152 レーンで 0.33 秒、3072 レーンで 0.55 秒 (中央値)。
vmap した while_loop が全レーンの収束か 80 反復まで回るので、逐次の反復の待ち時間が
支配的。初期値を減らしても速くならず、呼び出しをまとめると速くなる。

**変更** (既定で有効、各定数で切れる):

| 変更 | 内容 |

### 実機での実行 (`run_camera_pipeline_test.py --auto-execute`)

押し込み終了 (「どうぞ」の発話) から **4 秒後** (`--side-by-side-delay`) に「一緒に
横に並びますね」と発話して動き出す。押し込み後の把持画像の保存
(`--grasp-capture-duration`、既定 3 秒) は動き出すまでで打ち切る。各区間は最短 **0.2 秒**
(`--side-by-side-segment-time`)。移動中は首で人の顔を追う。押し込みを最終補正で解き直したときは、補正分の
関節角の差を横並び移動の各 waypoint にそのまま足す。横並び移動が解けなかったときは実機を
動かさない (`--speech-transition-fail-text` を発話)。
各区間の所要時間 (速度・加速度の上限) の決め方は
[dev_tools.md](dev_tools.md) の「`--auto-execute`: 実機での実行速度とログ」参照。

握りの向きを自由にしたバッチ IK は回転の拘束が違うので別のソルバーになり、別に
コンパイルされる。実機ノード・`plan_handshake_motion.py` の warmup で台車の全可動域で
1 回解いておく (`sbs.warmup_batch_ik`。最初の呼び出しを狭い可動域で行うと以後の結果が
壊れる既知の不具合の回避も兼ねる)。

### 人体との距離を 5 cm に (2026-10-14)

実機 (2026-10-13) では横並び移動の成功率が低かった。保存した骨格・押し込み姿勢
(押し込みまで解けた 13 人、体幹のずらし 7 cm) から `plan_transition` だけを解き直し、
検証の人体との距離を変えて比べた (6 cm の結果は実機ログの試行 10・13・15・18 と一致)。

| 人体との距離 | 6 cm | **5 cm** | 4 cm | 3 cm | 2 cm | 1 cm | 0 cm |
|---|---|---|---|---|---|---|---|
| 移動先まで 100% | 5/13 | **7/13** | 7/13 | 7/13 | 8/13 | 9/13 | 9/13 |
| 成功した経路の人体との最短距離 | 8.7 cm | 5.6 cm | 5.6 cm | 7.8 cm | 1.9 cm | 2.9 cm | 1.8 cm |

- 6 cm で落ちるのは、ほとんどが押し込み直後 (経路の最初の waypoint) に胴体の円柱
  (肩〜腰) へ 0.4〜4.5 cm まで近づくもの。
- 0 cm でも残る 4 人は距離と関係ない (自己干渉: 左前腕 x 太もも・親指の箱 x 胴体、
  腕が掌に届かない、関節角の飛び)。
- 移動先のバッチ IK の人体マージンも同じ値に緩めても成功数は同じか減り、時間が延びる
  ので 6 cm のまま。
- 合成データは 6 cm で全員通り、0 cm まで緩めても変わらない (実機の失敗を再現しない)。
- 1〜2 cm まで緩めればさらに 1〜2 人増えるが、人に 2 cm 前後まで近づく経路が選ばれる
  ので 5 cm にした。

### 軌道最適化の warmup の型

接近の軌道計画で最適化まで進んだ人の最初の 1 回が約 9 秒遅かったのは、**各腕の初回の軌道最適化の
再コンパイル**だった。skrobot の `JaxBackend` は最初に作られた時に `jax_enable_x64` を有効にする
(バッチ IK が作る) ので、バッチ IK より先に走らせた warmup は float32、本番の solve は float64
でコンパイルされ、warmup が効いていなかった (`JAX_LOG_COMPILES=1` で `jit(solve)` が 2 種類
コンパイルされるのを確認)。`plan_handshake_motion.py` は warmup の前に x64 を有効にして揃えている。
実機ノード (`run_camera_pipeline_test.py`) は IK の warmup が先なので元から揃っている。
初回だけ f64 の warmup がコンパイルされ、以後は永続キャッシュが効く。

## 5.5 腰を上げない (押し込み・横並び)

hover で沈んだ腰を、押し込みや横並びでまた浮かせると無駄な動きに見える (以前は押し込みで
34/61 人が 1 cm 超、最大 11 cm、横並びで 45/58 人が最大 26 cm 上がっていた)。腰の高さは
脚 (足首・膝) の角度だけで決まり、足首が大きい・膝が小さい (より曲げる) ほど低いので、
**脚を腰が高くなる側へ動かさない**ことで防ぐ。

- **押し込み** (`solve_press_in`、`PRESS_IN_LEG_RISE`、`--press-in-leg-rise`):
  各点の IK の前に足首の下限・膝の上限を**直前の姿勢の角度**にする (最初は hover)。終わったら
  元の可動域に戻す。`strict` (既定) は解けなければ押し込みの失敗、`fallback` はそのときだけ
  制限なしで解き直す、`off` は制限なし。
- **横並びの移動先** (`solve_goal_candidates`、`GOAL_LEG_RISE`、`--goal-leg-rise`):
  バッチ IK は関節可動域をキャッシュするので脚を制限できない。解いた候補の腰の高さを見て、
  押し込み終了時より `GOAL_LEG_RISE_TOLERANCE` (1 cm) を超えて高い候補のうち、超過が
  `GOAL_LEG_RISE_REPAIR_MAX` (10 cm) 以下のものは**脚を押し込み終了時の角度に直して**残す
  (腕はこのあと脚を固定した押し込み IK で解き直す)。それより高い候補は捨てる。腰を上げない
  候補が 1 つも出ない人がいた (最小で 1〜3 cm 高いだけ) ための修復。
- **横並びの経路** (`plan_path`、`cap_leg_rise`): 脚は押し込み終了時から移動先へ関節ごとに
  線形補間するが、腰の高さは関節角に対して凹なので、端点が同じ高さでも途中で膨らむ (最大
  2.4 cm)。補間した脚の腰が直前の waypoint (と押し込み終了時) より `PATH_LEG_RISE_TOLERANCE`
  (3 mm) を超えて高いときは、膝をより曲げ (足りなければ足首を上げ) て抑える。脚も IK で
  動かすとき (`free_legs`) は、足首の下限・膝の上限をその waypoint の脚の角度にする
  (`_press_ik` の `leg_floor`)。

## 6. 検証していない区間・姿勢

| 区間・姿勢 | 理由 |
|---|---|
| 押し込み区間の人体との干渉のうち、差し出された手まわり (掌・指・同じ側の前腕) | 掌に触れる姿勢そのもの (手まわり以外は 5 cm、自己干渉は検証する) |
| 最終補正で解き直した押し込み区間 | 計画時と同じ曲線で、目標の変化は 0.10 m・30° 以内とみなす |
| lead-in のうち人から 1 m より遠い部分 | 人体に届かないとみなす |
| 首の補間 (`blend_head_to_post_process`) 後の接近区間 | 首の動きを前倒ししているだけとみなす |
| 横並び移動の、ロボットの差し出す腕の肘から先 × 人の差し出した手・前腕 | 手を合わせている |
| 横並び移動の waypoint の間 | 1 区間 10 cm・10°・関節角 20° 以内に刻んでいる |
| 実機で最終補正の差を足した横並び移動の waypoint | 補正は数 cm 以内とみなす |

## 7. 事後検証のモデルの比較

合成人物 (`run_pipeline_test.py 100` の seed 1 と seed 2、IK 対象 8 + 11 = 19 人、
`--plan-motion --side-by-side-transition`、2026-10-15 に現行コードで測り直した)。IK・軌道最適化は
どれも指なし + 手の箱、自己干渉の許容 0 mm。

| `--collision-verify-model` | IK が解けた | 押し込み区間まで | 軌道が通った | 横並び 100% | IK / 軌道計画 / 横並び計画 [秒/人、平均] |
|---|---|---|---|---|---|
| **`mixed` (既定)** | **18** | **17** | **17/17** | 17/17 | 0.46 / 0.10 / 0.51 |
| `nohand` (すべて箱) | 16 | 16 | 16/16 | 16/16 | 0.43 / 0.10 / 0.48 |
| `hand` (すべて指あり) | 18 | 17 | 17/17 | 17/17 | 0.46 / 0.19 / 0.61 |

- 箱は指より大きいので、人体との距離まで箱で測ると hover の候補を捨てすぎ、IK の成功が減る
  (hover の目標を変える前の 2026-10-01 の測定では 23 → 19 人、hover の人体距離で棄却された候補は
  9 → 52 件)。
- `mixed` と `hand` は成功数が同じで、`hand` は自己干渉の組が多いぶん軌道計画が約 2 倍遅い
  (0.10 → 0.19 秒) ので `mixed` を既定にしている。人体との距離は `mixed` も指ありモデルで測る
  ので、`hand` との差は自己干渉の判定 (指なし + 手の箱か、指ありか) だけ。
- 時間は他のジョブと GPU を共有して測ったので目安。

## 8. 表示用の検証 (判定には使わない)

`view_handshake_poses.py`・`view_handshake_motion.py`・`run_camera_pipeline_test.py` の
画面の状態表示は、**指ありモデル**の干渉ジオメトリと総当たりペア (指同士・指と他リンクを
含む) で `colliding_link_pairs` を計算し、許容誤差 `DEFAULT_COLLISION_VERIFY_TOLERANCE`
(0 mm) より深い貫通を表示する。許容誤差を変えられるのは `run_camera_pipeline_test.py` の
`--collision-verify-tolerance` だけで、ビューアの 2 つは定数のまま。IK・軌道計画の
採否は変えない。
